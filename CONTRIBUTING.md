# Contributing to IPX

IPX is a privately controlled proprietary technology project. Unsolicited code contributions are not accepted by default.

## Contribution authority

No pull request, patch, design, specification, documentation change, architecture proposal, or other contribution becomes part of IPX merely because it is submitted publicly.

External contributions may be accepted only after explicit review and any required intellectual-property, confidentiality, contributor, work-for-hire, or assignment terms are completed in writing.

## Why this policy exists

IPX contains commercially sensitive intellectual property and provenance is a first-class system requirement. The project must maintain a clear chain of authorship, ownership, dependency licensing, and authority for every production change.

## Engineering standard

Authorized contributions must:

- target the canonical `main` integration path through an approved review process;
- include tests or qualification evidence for behavior changes;
- avoid mocks or placeholders in production paths;
- preserve backwards compatibility unless a documented migration exists;
- document security, privacy, operational, and recovery consequences;
- identify third-party code or materials and their licenses;
- avoid secrets, credentials, customer data, and confidential evidence;
- update public documentation when user- or operator-visible behavior changes;
- preserve fail-closed evidence and claim qualification.

## AI-assisted development

AI and other software-development tools may be used as tools by authorized contributors, but the human contributor remains responsible for reviewing the resulting work, verifying originality and licensing boundaries, testing behavior, and accepting responsibility for the contribution.

## No implied license

Submitting feedback, an issue, or a proposal does not grant permission to use IPX proprietary materials beyond ordinary review of the public repository.
